# 设计规则

P3、D2、D3、D4 动手前读。规则写要求；例子用来说明，不当清单、不做门槛。

## 玩法

- **设计玩法，不设计演出**。“这里放一段广播”“这里有音乐”不是玩法，是把空场景甩给别人。玩法是玩家在这里做什么、要面对什么。
- **背景和玩法分开写**。背景交代这里发生过什么，可以写进氛围；玩法写成物件、事件和路线。
- **没有掩体战斗**。感染者不会远程攻击，掩体没有意义。优先用原版的交互：油桶、煤气罐、烟花箱、警报车、可推的道具。
- **小型特感交给导演**。普通感染者和特感的日常刷新由导演负责，只有很特别的场合才固定刷，比如 Tank、Witch。
- **每处 1–2 个玩法**，并且串进流程。一个地方塞太多玩法，哪个都不突出。
- **没意义的赶路比路短更糟**。长距离要么有玩法撑着，要么用载具、压缩或换路线去掉。
- **基础补给和特殊补给分开**：基础补给（写在 `standards/decisions.json` 的 `supply_base`）是通关需要的下限，每个安全屋和每个大事件前都必须放够；特殊补给满足探索欲望，不设上限。特殊补给不能从基础补给里挪，安全屋或大事件前的基础补给不够，全关总数够也不合格。标 `"special": true` 的补给不计入基础下限。
- **每个玩法写原版依据**：用哪个实体、哪张原版地图有先例。游戏里没有的东西不写。
- **玩家要能找到、看懂该做的事**：必须做的、按了没反应的、要二选一的、操作有代价的互动，要让玩家看得见、知道缺什么、事先有个提醒；惊吓、彩蛋、一眼能认出的物资和原版玩家熟悉的机制（如警报车）不提示。
- **提示点到为止**：像一句提醒，不把解法说死。

## 空间

- **只为会走到或看到的地方建模**。进不去的房间只是一扇关着的门；路线不经过的楼层不写内部，只写外壳和楼梯（或楼梯的可见段）。这条决定建不建，不决定建了以后空不空。
- **建出来的每个空间都要符合它的设计和用途**，没有互动物也一样。设计写清这是什么房间、出事后成了什么样（室内意图）；本来就该空的，写清为什么空。房间里摆什么、怎么摆，由生成线按用途判断。
- **室内照片难找，按用途合理补充**，不停下来问；只有用户点名要还原的地标必须有照片，缺了就问。
- **先外壳，再内部**。
- **允许适配化**。只把决定路线的事实查清楚：竖向通道、公共区、出入口、挑空。不在规划路线上的（外观、层数、路线不进的房间）按资料定，照片优先，标“推断”；路线上的位置、尺寸、编号可以按游戏性调整，标“改动”。
- **尺度先量原版再定**。按“能走过去”的最低值做会显得局促。原版的门、车、家具都比真实尺寸大 20%–60%。门首先是路：现实里窄的门在地图上要加宽，先保证能顺畅跑通，外观其次。
- **压缩和朝向都是可选项**，用不用都要写理由和参考。真实距离放得下、节奏合适，就不压缩。
- **资料不够就缩小可玩范围**，不要脑补。

## 数据

- 因地图而异的数值写进待决定列表，不写死在设计里，也不写死在脚本里。
- 生成器要读的东西都写成固定取值的字段，用游戏原名。只写成一句中文，生成器只能猜。
- 事件：结构写精确，手感选档位。
- 面数预算从设计阶段就开始管：超了上限，编译直接失败。
- 改设计前先查规划原文：规划里的决定是用户拍过板的。
- 规划里写定的设计不当作事实去问用户。规划写了“某组人从某处下到某扇门”，就照这个设计，不再问“那里有没有这条路”。

## 彩蛋

彩蛋在结构体和开放区定稿之后、收口之前做。内容不受复刻约束，格式照样严格。不改主线，不进规划统计。
