# P2 采资料并建索引

**目的**：给后面每一步准备好可查的事实。所有会话共用同一套资料，谁也不重复找。

## 做

1. **先采底**：
   - 地理数据：真实地点跑 `kit geo fetch`（OSM 轮廓、道路、水面）；虚构地点手写 `sources/geodata/world.json`（[format/world.md](../format/world.md)）。
   - 候选地点概况：每个候选地点写一页 `findings/<对象>.md`，说明是什么、大致结构、有没有室内资料。
2. **按问题查**：每次调研先写下要回答的问题，答上了就停。照片、结构细节等到 D2 做到那个结构体时再查。
3. **入库**：每条资料登记进 `sources/index.json`，字段见 [project-layout.md](../project-layout.md)。认不出拍的是什么的照片不入库；认错了不删，加勘误。用户口述当场入库（`sources/oral/`）。
4. **结论**：写进 `findings/<对象>.md`，每条引用资料编号。设计数据里的 `src` 也引用编号，这样从任何一个元素都能反查依据。

## 子 agent

**轻量档**，按问题派，每个子 agent 拿一组问题。它们只往 `sources/_inbox/<agent>.json` 写候选条目，格式同 `index.json`，不带 `id`。你用 `kit sources add <文件>` 合并编号，抽查等级标得对不对，合并完删掉 inbox 文件。派活格式见 [subagents.md](../subagents.md)。

## 完成

`kit sources check` 通过：编号唯一、文件存在、等级和用途合法、每条都有来源。无关和存疑加起来超过一半时，脚本会警告，说明调研方式要改。

## 常见坑

- 按地点批量搜图，大部分结果无关或存疑。
- 另一条主线不知道已经有什么，重复下载、重复找图。动手前先跑 `kit sources find`。
- 网络照片的标题经常写错；文字搜索失效时，图片搜索往往更可靠；官方资源防盗链的，截图入库。
