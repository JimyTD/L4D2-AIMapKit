# G6 布景与叙事（每关一次）

**目的**：道具、贴花、散落物按参照和摆放规则摆，每组写参照，脚本核对摆放。这一步只有脚本门槛。

## 读

G2 的参照板；G5 的模型清单 \`work/models.json\`；美术规范的摆放规则；kinds.json 里 need 含 dressing 的元素（space、atmosphere）；开放区和结构体的空间、路线、门。

## 做

1. **布景设计文件** \`work/L<nn>/dressing/<段或结构体>.json\`，每组一条：挂靠的设计元素（elements.json 的 key；路线写 <开放区 id>/route/main）、排法（规范里的哪种）、模型或贴花、数量、参照编号、依据（参照编号，或 atmosphere、事件的 key）。设计改了，按 key 找到受影响的组，只改这些组。
2. **按摆放规则摆**：朝向跟数据走（沿线、靠墙的对齐长边，正面朝房间或路）；不随机转角；立着放，倒着的只放在设计写了“倒着”的地方；成堆的东西按规范里的几种排法选一种。
3. 布景挂在空间、门、路线上，不写死坐标。
4. **叙事痕迹按美术规范的旧化分档**：第 1 档（刚出事的痕迹：倒、散、血迹、半开的门）只放在设计数据写了的地方，每组必须引用那条 atmosphere 或事件的 key；没写的地方只做第 0 档（日常磨损）；第 2 档（损坏）只在设计点名时用。脚本检查：第 1、2 档的组都有引用。
5. **密度**不设数字门槛，不和原版比；由负责人在 G9 看新类型的视点时判断，判断结果写回规范（例：某类空间每间几组），之后各关照新规范。
6. **碰撞**：设计数据里的 fixtures、objects 按它的 blocks 字段决定挡不挡（翻不过去的按 G5 的 playerclip 条件）；布景自己加的物件用模型自带的碰撞，水平投影长宽都小于 dressing_noclip_max_u 的改成不碰撞。
7. **摆放核对**（脚本，每次生成后）：模型方向和数据方向差 ≤ placement_yaw_tol_deg；模型占地和数据外包重叠 ≥ placement_overlap_min；没写“倒着”的不许侧倒。另出一张俯视核对图（数据外包、模型占地、正面朝向，错的标红），交评审前先自己看。

## 产物

布景设计文件；布景平面图；\`build/L<nn>/placements.json\`（摆放记录）；俯视核对图 \`build/L<nn>/check/placement_*.png\`。

## 交给下一步

摆放记录 placements.json；灯具类模型的位置清单（脚本，从布景文件里的灯具组导出，带 lit），G7 按它放光源，不另找。

## 完成

剔除 0（出界、压路线、挡门、重叠）；摆放核对 0 条错；每组都有挂靠的 key 和参照编号，第 1、2 档的组都引用了设计数据。

## 常见坑

- 随机撒点：没有设计意图。
- 布景写死坐标：设计一改就落空（要挂在空间、门、路线上）。
- 规范只写“做什么”不写“怎么摆”：生成器自己发挥，随机转角、成片侧翻。
- 没有俯视核对图：摆错只能靠负责人在编辑器里发现。
- “看得出出了什么事”这种写法：每段都撒血迹，痕迹和设计对不上。
