# D5 整关收口与合成

**目的**：把整关合成一份 `spec.json`，并跑一遍所有跨文件检查。这一步只有脚本门槛，不需要用户拍板。

## 做

1. **事件表收口**：列全规划里的事件。结构写精确：来不来 Tank、来几只、靠什么结束、守多久。手感只选档位：每波多少只、间隔多久，档位的数值在 `strength_table`。物资写游戏原名和数量。普通感染者和特感交给导演，不写。
2. **定 Hammer 原点**：在 `layout.json` 的 `origin_m` 和 `origin_why` 里写。原点要让整关落在范围内，边距按 P3 的值。压缩和朝向已在 D1 拍板，这里照做。
3. `kit spec <n>`：合成并核验。核验内容包括：每个片段自己通过；规划条目全部落地；出入口和出口都有着落；起点一路通到终点；事件都有触发、引用都找得到；不重叠；标高衔接；面数在预算内；衔接安全屋和相邻关用的是同一个结构体文件。

## 完成

`kit spec <n>` 全部通过。

## 常见坑

- 触发和物资只写了一句中文，生成器只能猜。
- 写了游戏里不存在的东西，或者把普通特感一只一只写死。
- 门外的地面改了，台阶没跟着改。
