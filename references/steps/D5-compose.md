# D5 整关收口与合成

**目的**：把整关合成一份 `spec.json`，并跑一遍所有跨文件检查。这一步只有脚本门槛，不需要用户拍板。

## 做

1. **事件表收口**：列全规划里的事件。结构写精确：来不来 Tank、来几只、靠什么结束、守多久。手感只选档位：每波多少只、间隔多久，档位的数值在 `strength_table`。物资写游戏原名和数量。普通感染者和特感交给导演，不写。
2. **定 Hammer 原点**：在 `layout.json` 的 `origin_m` 和 `origin_why` 里写。原点要让整关落在范围内，边距按待决定列表的 `map_margin_u`。压缩和朝向已在 D1 定下，这里照做。
3. `kit spec <n>`：合成并核验。核验内容包括：每个片段自己通过；规划条目全部落地；出入口和出口都有着落；起点一路通到终点；事件都有触发、引用都找得到；不重叠；标高衔接；面数在预算内；衔接安全屋和相邻关用的是同一个结构体文件。

   同时顺手写出三份给后面用的清单（脚本生成，不手改）：
   - `elements.json`：这一关全部设计元素的扁平表（`key`、所属、类型、原文标签、来源等级、是否彩蛋）。`key` 由所属/类别/楼层/id 拼成，整关唯一；生成线用它记下每个面、每个实体属于哪个设计元素。`key` 只做整体比较，不要按 `/` 拆（id 里可能带 `/`），要各部分就读行里的单独字段。重名时 `kit spec` 核验不过。
   - `followups.json`：所有待跟进项，每条有唯一 `key`、状态和交给谁（用户、生成线、试玩）：问题、规划偏差、标“假设”的元素、玩法先例待核、暂定的标准、盲审的设计问题。
   - `handoff.json`：D7 交接的机器可读版：spec 是否通过、读哪些文件、每个结构体和开放区引用的资料、交给生成线的待跟进项。

## 完成

`kit spec <n>` 全部通过。

## 常见坑

- 触发和物资只写了一句中文，生成器只能猜。
- 写了游戏里不存在的东西，或者把普通特感一只一只写死。
- 门外的地面改了，台阶没跟着改。
