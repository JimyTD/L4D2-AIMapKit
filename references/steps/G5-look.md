# G5 外观、模型与地标（每关一次）

**目的**：材质、立面、自制模型、地标按参照做到成品，模型和贴图编译后核对。这一步只有脚本门槛。G5、G6、G7 在同一次生成里一起跑，分开检查。

## 读

G2 的参照板 `work/refs/refs.json`（外观类型、自制清单）；G3 的构件记录 `build/L<nn>/parts.json`（G4 已并入实体记录）；美术规范（材质、模型、摆放、标识）。

## 做

1. **外观规则**：每个可见面的材质、每个模型，都由 `work/style.json` 里的一条规则决定；布景模型的规则是布景文件里的组（[G6](G6-dressing.md)）。
   - **按类**的规则管一类构件，**按 key** 的只管一个设计元素，用于例外。按 key 优先；几条按类规则同时管到时，按规则文件写明的先后。
   - 分类方式由项目定，默认“部位槽 × 外观类型”；分类用到的值必须能从构件记录和 elements.json 的字段取到。
   - 每条规则有唯一 id，写参照编号，或标“推断”并写美术规范节号。
   - 构件记录每行的 rule 记用到的规则 id（几个面用了不同规则时写列表，布景组写 `dressing:<文件>/<组 id>`）。via 按行记：有可见面没有规则管到记“匹配失败”，没有可见面记“无外观”，用到按 key 规则记“按 key”，其余记“按类”。不按名字关键词猜。
   - 工具材质的面不算可见面。made_by 为 shell 的行同样要有规则。有规则不等于成品，成品看 status。
2. **立面贴图**：凹进的结构和不能通行的开口都画在这里（G3 的预算规则依赖它）。参照板里这一类型有照片的，做透视校正、裁切、按开间拼；没有照片的，用 Blender 程序材质按开间参数烘焙。每张写来源（照片编号或“程序生成”）。
3. **表面细节**：墙裙、踢脚、门框窗框、路缘石、地砖拼缝，不能一整面平铺。
4. **结构细节**用模型和贴花：栏杆、窗台、设备机位、管线、扶手、招牌。
5. **自制模型**：部件表 → Blender 后台 → 多角度渲染回读、和参照照片比对 → SMD → studiomdl → 打包。每个模型附参照编号和预览图；部件表、Blender 脚本、自制贴图源图放 `work/assets-src/`。
   - **坐标约定**写在美术规范里，所有模型一致（例：正面 +x，沿墙、沿线的方向是 y）；摆放代码按这个约定算朝向。
   - **精细档位**按美术规范的三档定，三角面数超出所在档的范围就报错。
   - **禁止篡改尺寸与占位替代**：不得为了通过检查删墙、挖大块空洞、撑大门洞，或用 `modelscale` 缩放非门扇模型、换成占位方块来塞进空间或绕过碰撞（kit verify B1、B2 会拦）；确实放不下的原样保留并登记 `gaps.json` 交回设计。
   - **编译后核对**（脚本）：读编译出来的模型外包盒，和部件表的外包盒逐项比，对不上就报错、不进地图。编译工具会改变模型朝向，只看编译前的预览图查不出来。
   - **碰撞**：用模型自带的碰撞体（单独做的凸包），不在模型外面另包不画的 brush。设计数据里，物件（fixtures、objects）blocks 为 true 并且 vault 为 false 的，以及封路（blockers）和 boundary 里 kind 为 barrier 的段 cross.survivor 为 false 的，才在数据外包上加 playerclip。
6. **地标**按参照做专用外观；地标级模型的三角面范围按精细档位。
7. **自制贴图编译后核对**（kit verify 的 R2、M2、T1、T2）：VTF 是 7.4、尺寸是 2 的幂；一个面上贴图横竖缩放差不超过 texture_stretch_max；**文字不镜像**：贴图的 u 轴（向右）叉乘 v 轴（向下）和面的朝外法线点积为负才是正的（缩放为负会翻转方向；srctools 的 Side.normal() 指向刷子里面，不是朝外法线）。带文字的材质在 decisions.json 的 text_materials 里列出。

## 产物

- `work/style.json`：外观规则，项目共用。结构由项目定，每条规则有唯一 id 和参照编号（或“推断”加规范节号）。
- `work/models.json`：模型清单，`[{"path", "size_u", "tier", "axis_ok", "refs"}]`。
- `work/licenses.json`：素材来源和许可记录。
- `work/assets-src/`：自制资源的源文件。
- materials/<项目>/、models/<项目>/（编译产物）；模型预览图。

## 交给下一步

构件记录每一行的 rule 和 status（白盒 → 成品）；模型清单 models.json，G6 只从清单里取模型摆。

## 子 agent

**主模型档**：自制模型一件一个子 agent（部件表、建模、渲染回读、编译后核对），交回模型路径、预览图、参照编号。**轻量档**：在原版资源包里按需求找候选模型，交回路径、尺寸、能不能做静态道具；主 agent 选。

## 完成

- **`kit verify <关号> --step G5` 通过**（[verify.md](../verify.md)）：没有缺失或 0 字节的资源、vbsp 没丢掉静态道具；打包的贴图是 VTF 7.4、尺寸是 2 的幂；文字不镜像、不超出承载面；三角面数在档位内；贴图不拉伸；以及 G3、G4 的各项。生成线自己写的检查只作自查，不作完成依据。
- 先快速档后完整编译（[verify.md](../verify.md) 的“快速档和完整编译”）：带外观和摆件快速编译，`kit verify <关号> --step G5 --build quick` 除“待完整编译”的项以外全过，才开始完整编译；完整编译后再跑一次 `--build full`。快速档上看得见的面不能有白盒材质（Q1）。
- 自制模型编译后外包盒和部件表一致（部件表是 G5 自己的产物，由本步 agent 核对）。
- 构件记录里没有“匹配失败”；每个 rule 都能在 style.json 或布景文件里找到，规则都写了参照编号或“推断”。

看预览图才能判断的（正面朝向、比例、主色），由本步 agent 逐张查，结果写进 `work/L<nn>/manual-checks.md`。

## 常见坑

- 标识文字写反（包括用负缩放翻转的）。
- 原版模型没按静态道具编译，vbsp 直接删掉。
- Blender 材质槽顺序错了颜色就错位。
- 精细程度每关重新问一遍：档位没写进规范。
- 只看编译前的预览图：编译后模型转了 90°，摆进地图全部朝错。
- 模型外面另包不画的碰撞 brush：模型一转向，看不见的墙留在原处。
