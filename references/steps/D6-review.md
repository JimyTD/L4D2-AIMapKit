# D6 整关评审与盲审

**目的**：确认整关写清楚了，一个不了解背景的人也能看懂；用户整关拍板。

## 做

1. `kit page <n>`：生成整关评审页 `level.html`（给人看的单文件，agent 不读它）。页面上有路线展开条带：按距离把路线拉直，标出沿途的事件、物资、守点和玩法，用户靠它判断节奏。
2. **盲审**：派一个**主模型档**的子 agent，不给任何上下文，只给评审页路径和三个问题：路线怎么走？每段玩什么？哪里看不懂？原话存进 `design/detail/L<nn>/BLIND-REVIEW.md`。
3. **把盲审的每一条分进四类**：
   - **要用户定的设计问题**：留给用户，每条附建议，有选项列选项；
   - **数据错误**（写反、重复、描述过时）：核实后直接改，重跑核验；
   - **细想没问题的**：排除，每条写一句理由。盲审本来就该提出这类问题，它和主会话想法不同才有价值；
   - **评审页表达问题**：记下来作为 Kit 的问题，不问用户。
4. 交用户整关拍板，消息按 [review.md](../review.md)：
   - 要你定的：盲审里的设计问题；整关节奏（看路线展开条带：哪段事太多、哪段空跑）；
   - 只是告诉你的：已改的数据错误、排除的条目和理由、记下的 Kit 问题。
5. 用户的意见写进 `design/REVIEW-LOG.md`，每条标“AI 本可避免”或“只有用户知道”。

## 完成

用户拍板后跑 `kit approve L<nn>/D6`。改数据时变成“拍板后已修改”的单元，只要没改设计，一并登记：`kit approve L<nn>/D6 L<nn>/structures/<id> …`。
