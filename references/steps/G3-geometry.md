# G3 几何（每关一次）

**目的**：把结构体和开放区建成 brush 几何，同时记下每个构件是什么、该不该换。这一步只有脚本门槛。

## 读

spec 里的结构体、开放区、总图；美术规范的预算规则。

## 做

1. **结构体**：外墙线围成实心体，把空间、楼梯间、门洞、要挖的开口当空腔挖掉；没写的房间自然是实心（门后不建）。
2. **开口**：按 access，walk、view 挖开（view 装玻璃），none 画在立面贴图上。凹进的结构画贴图，凸出的结构保留实体。
3. **竖向和挑空**：楼梯逐跑建踏步（func_detail），踏步上盖一层不画的斜坡碰撞，走起来不颠、AI 寻路顺；踏步和碰撞的做法用 `kit game find` 在原版地图里找楼梯先例，选一处，出处写进生成器注释，材质按部位槽取；往上封堵按 build_risers；挑空通到 to_level 层顶，回廊边建栏杆，采光顶做玻璃；电梯建井道和轿厢。
4. **开放区**：各段按 piece_order 合成；段间接缝不建出口；共用的栅栏只建一次；地面分区、封路、边界、台阶。
5. **范围外**：按预算规则，只沿可玩范围外缘封一圈 playerclip，远处地基不画顶面。
6. **可见性优化**（生成规则，脚本自动放）：
   - 连通室内外的门洞、商铺门口自动加 areaportal，门关着或看不到门里时不渲染室内。前提：门洞两侧的空间必须被墙、楼板完全隔开，没有别的缝；半开放的地方（敞开的商铺门面、没墙的雨棚下）不加，否则编译报错或失效。
   - 不负责挡视线的构件（踏步、栏杆、台阶、柱子、窗台、小构筑物）一律 func_detail，只让墙、楼板、地面切分区。
   - hint：在每个结构体外墙的每个凸角，沿两面外墙的延长线各放一块竖直 hint，高度到外墙顶；开放区不另放。
7. **构件记录**：每个构件按部位槽取材质（白盒阶段每个槽指向一种开发材质），生成时记一行（字段见“交给下一步”）。白盒阶段不用决定换成什么，但“这个要换”从这里就知道。
8. **不静默退回**：没有外观规则管到的可见面，不悄悄退回灰盒；via 记成“匹配失败”，在报告里单列，G5 处理。白盒阶段每个部位槽有一条指向开发材质的按类规则。
9. **看不见的面画 nodraw**：贴地的底面、贴墙的背面、封死的面由生成器画成 nodraw；看不见的整体本来就不建。所以没有“看不见所以留着白盒”的情况。
10. 预算按美术规范的预算规则；超了先看是哪类构件占大头，再按规则改做法（如凹进的改画贴图）。

## 产物

`build/L<nn>/instances/<结构体>.vmf`、`build/L<nn>/<地图>.vmf`（内部中间产物，不对外交付）、`build/L<nn>/report.json`、`build/L<nn>/stamps/G3.json`。

## 交给下一步

**构件记录** `build/L<nn>/parts.json`（脚本，每次生成整份重写）：每个 brush 构件、每个模型、每个实体（G4 并入）、每个挖出的空腔一行。字段：

| 字段 | 内容 |
|---|---|
| element | elements.json 的 key，或 null |
| owner | 结构体或开放区 id，每行都填 |
| made_by | design（对应设计元素，element 必填）；shell（结构体外壳和实心部分：外墙、楼板、屋顶、挖空后剩下的内墙，element 为 null）；generator（生成器自己加的 areaportal、hint、外缘 playerclip、远处地基，element 为 null，另写 what） |
| slot | 部位槽：外墙、门扇、可翻越物…… |
| asset | 现在用的材质或模型 |
| via | 按类 / 按 key / 无外观 / 匹配失败（见 [G5](G5-look.md) 的外观规则） |
| rule | 用到的外观规则 id；一行几个面用了不同规则时写成列表 |
| status | 白盒 / 凑合 / 成品 |
| 位置和外包盒 | G10 按坐标反查用 |

原文标签和类别从 elements.json 取，不另存。element 不在 elements.json 里的行，只允许 made_by 为 shell 或 generator。给人看的 `PARTS.md` 按部位槽和状态汇总（例：“门扇 N 个，白盒 a、成品 b”），匹配失败的单列。

## 完成

- vbsp 无漏点。
- brushside ≤ map_budget_ratio.goal × brushside_cap；brush ≤ map_budget_ratio.goal × brush_cap。
- 坐标在 ±(16384 − map_margin_u) 以内（[engine-facts.md](../engine-facts.md)）。
- 可见性（脚本）：report.json 的 vis_ratio（每个分区平均看得到的分区数 ÷ 分区总数）低于 decisions.json 的 vis_ratio_max；第一次实测后由生成线填暂定值、写 why，不问负责人；超了才由 AI 看是哪一片出了问题，改法写回生成规则。
- **覆盖检查**（脚本）：kinds.json 里 need 含 look 的 key，加上 spawn（对应 info_target）和 event（对应 logic_relay，G4 后查），在 parts.json 里至少有一行。space 对应生成器挖这个空腔时记的一行；access 为 none 的 opening 对应它所在外墙立面那一行（立面行写上它覆盖的 opening key），不另要一行；link 对应它指向的那扇门，不另要一行；同一个轮廓的 shown_structure 在任一段有一行即可。没有的单列，“不建”的写理由，其余算错。
- 日常迭代用快速档（vvis、vrad 都 -fast），完整编译只在 G9 交付时跑。

## 常见坑

- 凹进的结构全用 brush 挖出来，面数暴涨（应画贴图）。
- 改成 func_detail 不减 brushside。
- 斜放的楼每个面都会多出 bevel 面（朝向由 D1 定，代价已算进预算）。
- 范围外的 playerclip 和地基填满整个外包矩形，大量面数浪费在玩家到不了的地方。
- 没有 areaportal、hint，几乎每个分区都看得到整张图：完整 vvis 很慢，帧率有风险。
- 生成器知道每个面是什么、该不该换，却不记下来：精修只拿到“还剩多少面白模”，哪些东西、该换成什么全靠人想起来。
- 按名字关键词匹配，没匹配上就悄悄退回灰盒。
- areaportal 两侧没封严：编译报错或失效。
