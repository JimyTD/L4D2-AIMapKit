# D2 内部结构设计（每个结构体一次，一个一拍板）

**目的**：把每个可进入的结构体写成生成能直接照着搭的数据：先外壳，再竖向通道，最后只写需要的内部。

动手前读 [rules.md](../rules.md)。格式见 [format/structure.md](../format/structure.md)。

## 做

1. **先查清决定路线的结构事实**：竖向通道有几处、在什么位置，公共区在哪，出入口朝哪，有没有挑空。先跑 `kit sources find <对象> --use structure`。查不到再问用户，问时附上你的判断。位置、尺寸、编号这类不影响感觉、也不影响流程的细节，按游戏性定，来源标“改动”。
2. **外壳**：从外面看得到的部分和出入口。台阶要接上门外的地面。
   - 规则建筑（平面轮廓加楼层）：用“轮廓按层拉伸 + 立面规则”表示，格式已经支持。只有外壳的结构体可以用 `kit detail scaffold facade` 起稿。
   - 不规则结构体（山洞、溶洞、异形建筑等）：现有格式表达不了。停下来，向用户说明需要表达什么、你建议怎么表示，由用户决定。
3. **竖向通道**：楼梯、坡道、梯子、竖井。约定全部写清；往上要封堵的，写明要建几级。
4. **内部**：只写会走进去或看得到的空间。进不去的房间只是墙上一扇关着的门。跨层的空间写成挑空。
5. **物件**：按三档随结构体一起写（[format/structure.md](../format/structure.md)）。翻越、视线写成字段，触发接到事件表。
6. 大的结构体可以拆成一个外壳文件加每层一个文件（`parts`），改一层只需读那一层。

## 命令

`kit detail structure <文件>`：核验并生成 `.build.json`（交给生成）、`.check.json` 和 `.html`（评审页）。

## 子 agent

**轻量档**做两件事：
- 只有外壳的结构体，按脚手架批量起稿，起完必须过 `kit detail structure`。
- 在当前结构体评审期间，并行调研下一个结构体的事实，只交事实清单和资料编号，不做布局判断。

## 完成

`kit detail structure` 全部通过。按 [review.md](../review.md) 交用户拍板，然后跑 `kit approve L<nn>/structures/<id>`。

## 常见坑

- 不看证据，按惯例脑补。照片和口述看得出来的，按看到的写；没有证据的，标“假设”并挂一个问题。
- 改设计前没查规划原文。规划里的决定是用户拍过板的。
- 做完一整关才交，错了要全部返工。
