# G2 美术参照（每关一次）

**目的**：在建模型、做贴图之前，先定下每样东西照什么做。地标逐个找参照，其余按外观类型共用，远景按规范。这一步只有脚本门槛；地标缺资料的提问攒到 G4 之后的停顿。

## 读

spec 和 `grades.json`（分级、地标）；G1 的种类清单 `build/L<nn>/kinds.json`；atmosphere 文字；资料库（`kit sources find --use look`）；项目美术规范。

## 做

1. **依据有三种**，写明编号：① 现实参照：资料库照片和 findings（资料编号）；② 规范参照：美术规范的条目 id；③ 设计点名的原版参照：设计案写了参照某张原版关卡时，按 G0 的方法只查点名项。
2. **按分级配参照**（分级来自 grades.json）：
   - **地标**：逐个找参照，补搜优先给它们；要有“官方”或“确认”等级的照片；补搜也没有的，列进缺口提问，同时按推断做。
   - **可进入、外立面级**和场地段：按外观类型共用一套参照；“存疑”等级的照片可以当风格参照。
   - **远景级**：不找照片，按美术规范做。
3. **资料库和参照板都是项目共用的**：同类型的参照以项目级参照板为准，前几关配过的直接引用；这一关只加新出现的类型和地标。先用 `kit sources find` 查已有资料，缺的按 [P2](P2-sources.md) 的规则入库。全景、街景截图入库时写清拍的是哪栋楼、哪一面，认不出的写“未定”，不靠坐标自动对应；补搜截图按 [tools.md](../tools.md) 的环境注意事项做。
4. **外观类型**由 G2 定，写进 `work/refs/refs.json` 的 types：`[{"type", "structures": [结构体 id], "why", "approved"}]`。每个结构体只属于一个类型；地标各自单独成一个类型；场地段按 `ground[].surface` 分类型。G5、G9 只读这张表。外观类型只决定共用哪组参照和风格，不影响能不能走、翻、看、触发（D7 的 affects 全为空），所以归生成线。
5. **自制清单**：对种类清单里 need 含 look 的每一种，原版资源按 `kit game model` 或原版 models/ 目录搜同类模型，CC0 按美术规范第 ② 层的素材库搜关键词；两处都搜过、记下了搜索词仍找不到的，才列进自制清单，每项写参照编号、搜索词、用在哪里（G3 跑过后再用构件记录对一遍）。不靠对着参照想。
6. **参照板**：`work/refs/refs.json` 给脚本检查；`build/refs/refs.html` 由它生成，最上面是待回答的缺口提问，下面是带缩略图的参照。
7. 自制清单一出来，Blender 建模就开工，和 G3 并行，不用等 G3。
8. **缺口提问**（不是拍板）：只在地标缺照片时列齐问题（例：某处背面或侧面长什么样、招牌什么颜色），攒到 G4 之后的停顿一起问。回答了按资料库规则记进 `sources/oral/`，各关复用；回答之前和不记得的，按推断做并在参照板标“推断”，流程不停。成品长什么样由负责人在 G9 看实物判断。

## 交给下一步

- refs.json：key 和部位槽、kind 用同一套名字，G5、G6 直接按 key 取参照；types 给 G5 定风格、G9 筛视点。
- 自制清单，每项带搜索词。
- 缺口提问：G4 之后的停顿一起交。

## 子 agent

**轻量档**：地标缺资料时按缺口补搜照片，交回候选照片和来源，由主 agent 按 P2 规则入库。

## 完成

每个地标、每种类型都有参照或标了推断，编号都能找到。参照检查脚本做出来之前，由本步 agent 读 refs.json 逐条核对这三项（编号在 sources/index.json 里查），结果写进 `work/L<nn>/manual-checks.md`。

## 常见坑

- 布景理由写成“按常见做法”，没有参照。
- 参照放在后面：白盒建完才发现地标没资料。
- 资料库多是网上搜来、来源存疑的照片，官方照片少；地标最容易缺照片，要最先补。
- 按单栋楼找照片：资料库按类型存，单栋往往查不到。
