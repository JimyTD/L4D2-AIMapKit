# D1 关卡准备（每关一次）

**目的**：开始画结构体之前，先定这一关的范围和预算。这一步默认不停下拍板：分级、分段、朝向按规则推出，地标在 P3 已经问过。只有存在压缩候选时，才交用户拍板压缩。

## 做

1. **分级**：把范围内的每个结构体写进 `design/detail/L<n>/grades.json`（[format/level.md](../format/level.md)），分为可进入、外立面、远景、省略。路线进入的是可进入，离路线近的至少是外立面。P3 定的地标（源文件 `landmarks`）标 `landmark: true`，告诉生成线哪个结构体要专门做外观。共享结构体看 `kit status` 列出的写入关：本关是写入关就由本关设计；不是，只走写入关已建的部分时只引用，要走得更深就在 D2 写扩展文件（kit status 会列为“扩展”）。
2. **开放区分段**：把开放区切成首尾相接的几段，每段两头接出入口或出口。按规划的段落切，不交用户。
3. **压缩**：在这一步决定，规划阶段只标了候选（路段的 `compress: true` 和 `compress_why`）。
   - **没有候选、整关也在预算内**：不压缩，在 `layout.json` 的 `compression` 写一句理由，不单独问用户。
   - **有候选**：出压缩方案 `compress.json`，用 `kit detail compress` 核验，它会生成压缩前后的对照图（两图并排，结构体不缩，只缩结构体之间的开阔段，图下列出每段压缩前后的长度和纯跑秒数）。交用户时附：对照图；方位和视线检查结果（该看到的地标压完还看得到吗、方向歪没歪）；你的建议和理由。用户要判断的是：压完以后这段路的感觉对不对、熟悉这里的人还认不认得出来。
   - 用户不是关卡设计师：只给他看得到的依据和明确的建议，不让他凭空定比例。
4. **朝向**：整关转不转、为什么。结构体斜放会多出 bevel 面，代价要算进预算。这是技术取舍，写清理由即可，不需要用户判断。
5. **面数初估**：`kit detail estimate <n>`，超预算就在这一步缩范围或降级。
6. **建事件表和总图**：建 `events.json`（先列全规划里的事件）和 `layout.json`。之后每写完一个结构体或开放区就登记进总图，每次核验顺带跑 `kit detail layout`。
7. 在 `design/detail/L<n>/README.md` 写下分级、地标、分段，以及压缩和朝向的决定。

## 拍板

- **没有压缩候选**：不停，直接进 D2。分级、分段、朝向会在 D2、D3 的详图和 D6 的整关页里被用户看到，有问题那时提。
- **有压缩候选**：交用户拍板，消息按 [review.md](../review.md)：评审页是压缩对照图；要你定的是压不压、压多少（附建议）；只是告诉你的是分级数量、分段、朝向和面数初估。

## 完成

`kit detail estimate` 在预算内，`layout.json` 写了压缩决定。有压缩候选时，用户拍板后跑 `kit approve L<nn>/D1`；没有候选时 `kit status` 自动显示完成。

## 常见坑

- 分段边做边切，到合成时才发现段与段接不上。
- 默认就压缩。真实距离放得下、节奏合适，就不压。
- 在规划阶段就让用户定压缩比例：那时看不到空间，只能拍脑袋。
- 把分级表、分段这类按规则推出的东西交用户拍板：他看不到空间，判断不了。
