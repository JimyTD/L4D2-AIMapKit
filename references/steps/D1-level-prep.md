# D1 关卡准备（每关一次）

**目的**：开始画结构体之前，先定这一关的范围和预算。

## 做

1. **分级**：把范围内的每个结构体写进 `design/detail/L<n>/grades.json`（[format/level.md](../format/level.md)），分为可进入、外立面、远景、省略。离路线近的至少是外立面。另外标出地标，告诉生成线哪个结构体要专门做外观。共享结构体如果本关是写入关，就由本关设计；不是写入关，只引用，并写明用到它的哪几个区。
2. **开放区分段**：把开放区切成首尾相接的几段，每段两头接出入口或出口。
3. **压缩和朝向**（交用户拍板）：
   - 压缩是可选项，用不用都写理由和参考。只缩结构体之间的开阔段，不缩结构体本身；方位不变，视线不被挡住。用了压缩要写 `compress.json`，用 `kit detail compress` 核验。
   - 朝向：整关转不转、为什么。结构体斜放会多出 bevel 面，代价要算进预算。
4. **面数初估**：`kit detail estimate <n>`，超预算就在这一步缩范围或降级。
5. **建事件表和总图**：建 `events.json`（先列全规划里的事件）和 `layout.json`。之后每写完一个结构体或开放区就登记进总图，每次核验顺带跑 `kit detail layout`。
6. 在 `design/detail/L<n>/README.md` 写下分级、地标、分段，以及压缩和朝向的决定。

## 完成

`kit detail estimate` 在预算内，用户对分级、分段、压缩、朝向拍板后，跑 `kit approve L<nn>/D1`。

## 常见坑

- 分段边做边切，到合成时才发现段与段接不上。
- 默认就压缩。真实距离放得下、节奏合适，就不压。
