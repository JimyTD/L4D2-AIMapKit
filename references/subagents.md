# 子 agent

## 为什么派子 agent

满足以下任一条才派：

- 产出的大部分会被丢掉，只需要结论（保护主 agent 的上下文）；
- 和主线互相独立，可以同时跑；
- 需要一双不知道背景的眼睛（盲审）；
- 用轻量档就能做好，可以省钱省时间。

## 档位由步骤页写死

每一步要不要派、用哪一档，已经写在步骤页里，不要临场决定。档位对应的具体模型在 `kit.local.json` 的 `agents` 里（P0 问过用户）。

| 步骤 | 任务 | 档 | 交回什么 | 怎么保证质量 |
|---|---|---|---|---|
| P2 | 按问题搜资料、认照片、初步分级 | 轻量 | `sources/_inbox/<agent>.json` 里的候选条目 | `kit sources add` 加 `check`；抽查等级 |
| P3 | 查玩法的原版先例 | 轻量 | 实体名、接线方式、出处 | 实体名过 `kit game classes` |
| D2 | 只有外壳的结构体批量起稿 | 轻量 | 结构体文件 | `kit detail structure` 全部通过 |
| D2 | 动手画之前，按结构体并行调研结构事实 | 轻量 | 事实清单和资料编号，不做布局判断 | 主 agent 核对来源后汇总 |
| D6 | 盲审 | 主模型 | 复述：路线、每段玩法、看不懂的地方 | 和设计对照 |
| G1 | 生成器改动后对已完成的关回归比对 | 轻量 | 三类结果：一致 / 修好了旧问题 / 退步 | 主 agent 看退步项 |
| G2 | 地标缺资料时按缺口补搜照片 | 轻量 | 候选照片和来源 | 主 agent 按 P2 规则入库 |
| G5 | 自制模型，一件一个 | 主模型 | 模型路径、预览图、参照编号 | 编译后外包盒核对通过 |
| G5 | 在原版资源包里按需求找候选模型 | 轻量 | 路径、尺寸、能不能做静态道具 | 主 agent 选 |
| G6 | 室内盲审，一栋楼一个；不给设计，只给每个房间人眼高度、不带标注的画面 | 主模型 | 每个房间：这是什么房间 | 主会话和设计的用途对照，对不上的改了重审 |
| G9 | 完整编译没过时读编译日志 | 轻量 | 原因和建议改法 | 主 agent 改完重编译 |
| 任何步 | 把文字转成固定字段、跑脚本汇总 | 轻量 | 改好的字段和核验摘要 | 脚本通过 |

**不派**：设计决定、解读用户意见、判断结构事实、写格式和规则。这些由主模型自己做。

## 规则

- 子 agent 只写派活说明里给它的那一个输出路径。编号、合并、提交只由主 agent 做。
- 子 agent 不和用户对话。
- **升级**：轻量档遇到需要判断的问题，停下来原样交回；同一个任务两次没过核验，改由主 agent 自己做。
- 环境不支持子 agent（`"subagents": false`）时，这些任务由主 agent 自己做。
- 每个会话同时派几个，按环境的并发上限（P0 查环境时写进 `agents.max_subagents`）。派几个由任务数决定：每个玩法、每个可进入结构体、每件自制模型一个。

## 派活说明的固定格式

```text
任务：<一句话>
档：<轻量 | 主模型>（照步骤页写的）
读：<文件路径列表>（只读）
写：<唯一的输出路径>
交付：<格式；对应 format 哪一页哪一节>
完成判定：<跑哪个命令，必须通过>
不要：改其他文件 / 联系用户 / 启动游戏 / 推送
遇到以下情况停下交回：<需要判断的问题>
交回：一段话：做了什么、没做成什么、需要主 agent 决定的问题
```

## 会话（不是子 agent）

每关的设计线、生成线怎么分段、谁开谁、同时能开几个，见 [sessions.md](sessions.md)。共享结构体的文件只有写入关能改；后一关要加内部，在自己关里写扩展文件。新会话的开场白只需要三句：用这个 skill；项目目录在哪；负责哪一关的哪一段。其余的它会按 SKILL.md 的开工顺序自己读。
