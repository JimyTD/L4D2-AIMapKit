# 链路 1：设计手册

版本：1.0（2026-11-09）

链路 1 把一个主题（真实地点或虚构概念）落成可以搭建的设计。分两个阶段：**规划**和**详设**。术语、来源等级、状态见 [../OVERVIEW.md](../OVERVIEW.md)；项目目录见 [project-layout.md](project-layout.md)；每样交付物的内容和底线见 [deliverables.md](deliverables.md)。

---

## 0. 怎么用这本手册

- **按顺序先完整做一版**。每一步的产出都要达到“可评审底线”（OVERVIEW 第 2 节），再交负责人评审。
- 负责人可能对任何一步提修改。改完从那一步往下重新推进，下游受影响的材料一起更新。
- **讨论阶段只读**：和负责人讨论方案时不改文件；负责人同意后连续执行已确认的范围；范围或关键决定变了，重新确认。
- 每完成一步，把结论写进对应文件。不要只在对话里说。

## 1. 规划阶段

回答：做几关，每关走哪、玩什么、节奏怎样。

### 步骤 1：定目标

和负责人确认：

- **真实度目标**：去过的人要一眼认出来，还是只借地点的气氛。这决定后面资料要采多深、改动能放多大。
- **规模**：几关，每关大约多长时间。
- **体验曲线**：全战役的压力怎么起伏，每关的情绪是什么。

产出：设计文档 `design/plan/DESIGN.md` 的战役概要部分（第一版）。

### 步骤 2：采资料并分级

- 能用的来源：地理数据（OSM、卫星影像、高程）、照片、官方全景和地图、视频抽帧、网页、游戏文件，以及**负责人和去过的人的记忆**。
- 每条资料进资料库，给编号，按对象归档，标来源等级（OVERVIEW 第 4 节）。
- 认错的资料不删，在索引里加勘误。
- 负责人口述的确认，往往比任何网络资料都准，当场记进 `sources/oral/`。
- 资料采到能支撑决策就停。缺的部分列成问题清单交负责人，不要无限搜索。

**常见坑**：

- 网络照片的标题经常是错的。要看画面本身能不能认出对象，认不出就标“存疑”。
- 官方页面的资源（全景、视频）常有防盗链；在浏览器里打开截图即可，截图同样进资料库。
- 搜索引擎对中文关键词的网页搜索经常失效，图片搜索更可靠。

### 步骤 3：定坐标和标尺

**这一步必须在画任何图之前完成**，否则后面会大面积返工。

- **坐标**：选一个原点，用米，x 向东、y 向北、z 向上。地理数据换算到这个坐标系，换算后用一个已知地物检查有没有镜像（例如“某块草地在卫星图上是绿色的”这种像素级检查）。坐标链路里任何一处翻转都会让整张图镜像，而且肉眼很难发现，所以这个检查必须自动化。
- **标尺**：1 单位 = 2.54 cm（1 英寸）。依据见 [../stage3-tools/HANDBOOK.md](../stage3-tools/HANDBOOK.md) 的“标尺”一节。
- **压缩原则**：建筑本身不缩，只缩楼与楼之间的空地。
- **范围预算**：一张图每个轴不超过 32768 单位，约 832 m；扣掉天空盒和边界，规划按 **730 m** 预算。注意这是**边长**，不是路线总长。
- **速度**：幸存者跑速 220 单位/秒，约 5.6 m/s；用来把距离换算成时间。

产出：项目的 `standards/`（坐标、标尺、范围、速度），以及规划工具里的坐标换算和防镜像检查。

### 步骤 4：切关卡

- 按“这里有没有玩法撑得住”选区域，不按距离和名气。一个地方再有名，没有玩法就不进主线。
- 相邻两关共用一个安全屋（衔接点），坐标完全一致。
- 关与关之间要有对比：室内对室外、高压对低压、白天对夜晚。
- 定每关的时间和天气。按需要来选：要不要观景、要不要看清远处、天气本身是不是玩法的一部分。

产出：战役概要补全（关卡切分、衔接点、天气时间线、节奏曲线）。

### 步骤 5：逐关设计

每关定：

- **路线骨架**：贴着真实地理走。路线用真实道路寻路生成，室内段限制在建筑轮廓里。
- **段落和场景**：每个场景 1–2 个玩法，前后串起来，前一段的东西最好能带到后一段用。
- **事件、资源、路障、守点**。
- **节奏和时长**：纯跑时间 × 2–3，加上守点等待时间；按压缩比例算游戏内长度。

设计规则（缺一条，负责人都会打回）：

1. **设计的是玩法，不是演出**。地方空，不要靠音乐、广播、影像来填。判断标准：玩家能不能因为它做出不同选择。
2. **背景和玩法分开写**。
3. **贴近游戏机制**。普通感染者没有远程攻击，不存在“掩体战斗”；优先用原版可交互物品（油桶、煤气罐、烟花箱、pipe bomb、警报车）；不发明游戏里没有的系统。
4. **小型特感交给导演**。只有 Tank、Witch，或者地形专门为某种特感准备时才写。
5. **一个地方的玩法不要太多**，每个场景 1–2 个，并串进流程。
6. **没意义的赶路比短更糟**。一段路只能空跑，要么加一个机制，要么压缩。
7. **资料不够就缩小可玩范围**，不要硬编。现实里已有的结构（防洪门、卷帘门、闸机）优先拿来当机关。

### 步骤 6：用游戏核实

- 每个玩法找原版地图的先例：直接读游戏文件里的地图实体，确认原版用什么实体、怎么连线做到的。
- 关键数值从游戏数据里读，不凭记忆：跑速、Tank 速度、台阶高度等。
- 核实不了的标“待实测”，进入链路 2 的白模阶段时验证。

读游戏文件的方法见 [../stage3-tools/HANDBOOK.md](../stage3-tools/HANDBOOK.md) 的“读原版资源”。

### 步骤 7：出图、校验、和负责人逐条过

- **规划图**：北向朝上，卫星底图，路线按模式区分（室外、室内、楼上、桥、载具），标出段落、事件、守点、资源、路障、刷怪口、安全屋；拥挤的地方加局部放大图。一张交互视图（分图层、可缩放），加每关一张静态海报。
- **自动校验**：朝向和防镜像、室内段不出楼、室外段不穿楼不下水、事件和资源都在路线上、刷怪口不在楼内或水里、安全屋衔接、范围预算、产物比数据新。
- **和负责人逐条过**：每关单独评审，评审时提出具体问题。结论当场写进文档，标“定稿”“讨论中”或“假设”。

规划阶段完成的标志：每关都定稿，总览图按定稿路线重画，校验全部通过。

## 2. 详设阶段

回答：每关的空间具体长什么样。规划阶段的路线只是近似（室内段沿建筑轮廓中线画），链路 2 拿着它还要自己做大量空间决定，这些决定按判别规则（OVERVIEW 第 1 节）属于链路 1。

详设按关进行，一关做完交链路 2，再做下一关。每关的产出放在 `design/detail/L<编号>/`。

### 步骤 D1：建筑分级

把关卡范围内每栋楼分级：

| 级别 | 含义 | 链路 2 要做什么 |
|---|---|---|
| 可进入 | 玩家能进去，列出开放哪几层 | 室内全部搭建 |
| 外立面 | 在可玩边界内或边界上，有碰撞，进不去 | 外壳和立面 |
| 远景 | 可玩边界外，只看得见 | 放进 3D 天空盒 |
| 省略 | 看不见 | 不做 |

### 步骤 D2：压缩布局，出空间总图

- 把关卡范围分成**刚性块**（一组相对位置不变的建筑）和**弹性带**（可以缩短的空地、道路、水面）。
- 压缩就是缩短弹性带，再把刚性块整体平移。规划阶段只在路段上标了压缩比例，这一步要落到每栋楼的新位置。
- 检查：楼和楼不重叠；方位关系不变（A 在 B 的西边，压缩后还在西边）；关键地标之间的视线还在；压缩后整关在范围预算内。
- 产出：空间总图（压缩前后对照）和每个刚性块的平移量。

### 步骤 D3：室内平面图

每栋“可进入”的楼、每个开放楼层一张：

- 墙、门、窗、楼梯、电梯井、房间功能，以及哪些门封死、怎么封。
- 标高、层高。
- 每个元素标来源。外轮廓来自实测；内部布局通常是推断：按楼宽判断中廊式还是单廊式，按开间切分房间。
- **先出推断版，附 5–10 个只有去过的人才知道的问题**交负责人。负责人答完再定稿；答不上来的标“假设”，按玩法需要设计。
- 校验：走廊连通；门宽至少能两人并排；平面不出外轮廓；所有路线上的门都在平面里。

### 步骤 D4：剖面图

只在有上下层玩法的地方做（楼座、中庭、台阶、楼梯间）：

- 层高、楼梯的位置和走向、高差、上下层之间的视线。
- 校验：台阶每级不超过 18 单位；楼梯宽度够两人并排。

### 步骤 D5：封路与可玩边界

- **封路清单**：每处封路定五件事（OVERVIEW 3.2）。原版常用的封法有车辆、施工围挡、碎石堆、沙袋、倒树、铁丝网、防洪门或卷帘门。
- **可玩边界**：沿边界每一段写清用什么封（墙、围栏、水面、陡坡），以及外面能看到什么。
- **远景清单**：边界外看得见的地标，按 3D 天空盒的方式做（Source 惯例按 1/16 比例摆在一个单独的盒子里）。

### 步骤 D6：搭建规格

把 D1–D5 合成一份机器可读文件交链路 2。格式见 [deliverables.md](deliverables.md)。合成时要能自动校验：所有路线上的门在平面里、封路不压路线、边界闭合、规格里没有未定义的引用。

### 步骤 D7：评审和交付

- 交负责人评审：空间总图、平面图、剖面图、封路与边界清单、待确认问题清单。
- 定稿后交链路 2。链路 2 做出白模、进游戏以后发现的问题，退回到这里改。

## 3. 规划工具

规划和详设都要出图和校验。可以复用的部分：

| 部分 | 通用 | 项目专属 |
|---|---|---|
| 坐标换算、影像地理参照 | 是 | 原点 |
| 室外栅格寻路（建筑、水面、围墙不可通行，道路代价低） | 是 | 围墙上哪些地方是出入口 |
| 室内寻路（限制在轮廓内，偏向中线） | 是 | — |
| 规划图渲染（海报、交互视图、局部放大图） | 是 | 配色、标题 |
| 自动校验 | 大部分 | 防镜像用的地物参照点 |
| 关卡数据 | — | 是 |

这些工具目前还没有通用实现，以后抽成通用代码放进本工程。

## 附录：常见错误

下面是实际走规划阶段时犯过的错，对应的规则都已写进上面的步骤。

| 错误 | 后果 | 对应规则 |
|---|---|---|
| 规划做到一半才定标尺，之前按 1 单位 = 1.905 cm 估算 | 所有尺度和时长都要重算 | 步骤 3 必须最先做 |
| 坐标在两处各翻转了一次 | 整张规划图南北镜像，评审时才发现 | 步骤 3 的自动防镜像检查 |
| 把有名但没有玩法的地点放进主线 | 评审时整段删掉，路线重排 | 步骤 4 的选区规则 |
| 用“放广播”“播放影像”填空 | 被打回 | 设计规则 1 |
| 设计了“掩体战斗” | 不符合普通感染者只会近身攻击的机制 | 设计规则 3 |
| 一栋楼没有室内资料，仍然打算整栋开放 | 只能硬编布局；最后靠负责人回答几个问题确定通行关系，并缩小可玩范围 | 步骤 2 和设计规则 7 |
| 规划阶段结束才发现缺室内细节、压缩后的布局、封路、可玩边界、建筑分级 | 链路 2 无从下手 | 详设阶段 |
