# 项目目录规范

版本：1.0（2026-11-09）

一个地图项目（例如一部战役）一个目录。按这个结构组织，不同的会话和模型都能直接找到东西。空骨架在 [../../templates/project/](../../templates/project/)。

## 1. 顶层

```text
<项目>/
  README.md          项目是什么、当前进度、从哪读起
  sources/           资料库：原始证据，只增不改
  findings/          结论：按对象整理的事实，引用资料编号
  standards/         项目级规则：坐标、标尺、范围、速度
  design/
    plan/            规划阶段的材料
    detail/L01/ …    详设阶段的材料，每关一个目录
  tools/             项目自己的脚本（数据下载、规划工具、适配器）；试验性脚本放 tools/prototypes/
  mapkit.json        链路 2、3 用的项目配置（进入搭建时才有）
  scenes/  maps_src/ assets/  build/    链路 2、3 的目录，见链路 3 手册
```

目录名一律用英文小写和连字符，中文名写在索引和 README 里。这样路径在各种工具和模型里都稳定。

## 2. 资料库 `sources/`

```text
sources/
  README.md          怎么查、怎么加
  index.json         总索引
  photos/<对象>/     照片
  panoramas/<对象>/  全景截图
  video/<对象>/      视频抽帧
  web/               网页摘录，每条一个 md
  geodata/           地理数据：OSM、卫星影像、高程
  game/              从游戏文件读出的实测数据
  oral/              负责人和去过的人的口述确认
```

**四条规则**：

1. **按对象归档，不按关卡**。关卡会调整，对象不会变。资料和哪一关有关，写成索引里的标签。对象名用英文短名，可以有层级，如 `main-building`、`main-building/interior`。
2. **每条资料有固定编号**：`S` 加四位数字，如 `S0123`。文档里引用编号，不引用路径。文件以后挪了、改名了，链接都不会断。
3. **原件不改**。认错了在索引里加勘误；不要删除或覆盖文件。
4. **口述也是资料**。负责人说“东侧入口有三级台阶”，就在 `oral/` 加一条，写日期和原话。

**`index.json`**：一个数组，每条：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `S0001` 起，只增不复用 |
| `type` | 是 | `photo` `panorama` `video` `web` `geodata` `game` `oral` |
| `path` | 是 | 相对 `sources/` 的路径；`oral` 指向 md 文件 |
| `subject` | 是 | 对象名；对象不明时用 `misc` |
| `grade` | 是 | 来源等级：实测、官方、网络、存疑、无关、确认 |
| `title` | 否 | 原标题 |
| `url` | 否 | 来源页面 |
| `media_url` | 否 | 原图或原视频地址 |
| `date` | 是 | 获取日期 |
| `note` | 否 | 画面里是什么、和对象的关系 |
| `tags` | 否 | 关卡、场景等标签，如 `["L05", "finale"]` |
| `errata` | 否 | 勘误数组，每条 `{date, text}` |
| `former` | 否 | 迁移前的旧编号或旧文件名，方便对照旧文档 |

**加一条资料**：放文件 → 在 `index.json` 末尾加一条（取最大编号加一）→ 有新结论就写进 `findings/`。

## 3. 结论 `findings/`

- 按对象一个 md：`findings/<对象>.md`。
- 每条结论写来源等级和资料编号，例如：`东侧入口有三级台阶。来源：确认（S0412），实测（S0203 台阶尺寸）`。
- 结论之间有冲突，以更高等级的为准，并写明冲突。
- `findings/README.md` 列出所有对象和一句话摘要。

## 4. 标准 `standards/`

项目级规则，一条一个 md：坐标系和原点、标尺、范围预算、速度。规划阶段步骤 3 产出，全项目都按它来。

## 5. 设计 `design/`

```text
design/
  plan/
    DESIGN.md        设计文档：战役概要 + 各关设计（规划阶段的主文档）
    data/            规划数据（如 levels.json）
    views/           规划图：交互视图、各关海报、底图裁片
    reports/         校验报告
  detail/
    L01/
      README.md      本关详设的状态和问题清单
      ...            见 deliverables.md
```

`DESIGN.md` 前半是战役概要（目标、关卡切分、衔接点、天气时间线、节奏曲线），后半每关一章。规模大了可以拆成 `CAMPAIGN.md` 和每关一个文件。

## 6. 不放进项目的东西

- 一次性的探索产物、过期的中间文件：验证完结论写进文档，产物删掉。
- 第三方工具和 Python 环境：放链路 3 工程的 `vendor/`、`.venv/`。
- 可以从脚本重新生成的大文件（影像瓦片缓存等）：不纳入版本管理。
