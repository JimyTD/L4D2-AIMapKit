# 链路 1 交付物

版本：1.0（2026-11-09）

每样交付物写清：内容、格式、可评审底线。“可评审底线”的通用要求见 [../OVERVIEW.md](../OVERVIEW.md) 第 2 节，这里只写各自的额外要求。

## 规划阶段

| 交付物 | 位置 | 内容 | 额外底线 |
|---|---|---|---|
| 战役概要 | `design/plan/DESIGN.md` 前半 | 真实度目标、规模、体验曲线、关卡切分表、衔接点表、天气时间线 | 每关一句话卖点；衔接点有坐标 |
| 关卡设计 | `design/plan/DESIGN.md` 每关一章 | 每关：职责、路线骨架、段落、场景与玩法、背景、导演与资源、技术风险、验收标准 | 每个玩法写“求生之路里的依据”；背景和玩法分开写 |
| 规划数据 | `design/plan/data/` | 每关的路线、段落、事件、守点、资源、路障、刷怪口、安全屋，坐标为米 | 能被规划工具读取并通过校验 |
| 规划图 | `design/plan/views/` | 交互视图 + 每关海报 + 总览 | 北向朝上；校验里有像素级防镜像 |
| 校验报告 | `design/plan/reports/` | 每项检查和结果 | 全部通过，或写明为什么接受失败项 |

## 详设阶段（每关一套）

位置：`design/detail/L<编号>/`。

| 交付物 | 文件 | 内容 | 额外底线 |
|---|---|---|---|
| 建筑分级表 | `buildings.md` | 关卡范围内每栋楼：可进入（开放哪几层）、外立面、远景、省略 | 路线经过的每栋楼都有级别 |
| 空间总图 | `layout.md` + 图 | 刚性块和弹性带的划分、每块的平移量、压缩前后对照图 | 楼不重叠、方位不变、在范围预算内 |
| 室内平面图 | `floors/<楼>-<层>.md` + 图 | 墙、门、窗、楼梯、房间功能、封死的门、标高 | 每个元素标来源；走廊连通；门宽够两人并排 |
| 剖面图 | `sections/<位置>.md` + 图 | 层高、楼梯、高差、视线 | 每级台阶不超过 18 单位 |
| 封路与边界清单 | `blockers.md` | 每处封路的五件事；边界每段的封法和外面能看到什么；远景清单 | 边界闭合 |
| 搭建规格 | `spec.json` | 以上内容的机器可读合集 | 能通过自动校验，没有未定义的引用 |
| 待确认问题清单 | `README.md` | 给负责人的问题，每题注明影响哪个交付物 | 每个“假设”都对应一个问题 |

### 搭建规格的格式

**状态：待定义**。第一个详设试点完成时定第一版，并和链路 3 的场景描述格式对齐。至少包括：

- 关卡原点和范围；
- 刚性块和它们的平移；
- 建筑：轮廓、级别、开放楼层、层高；
- 楼层平面：空间（多边形、标高、功能）、墙、开口（门、窗，带宽高和封死与否）、楼梯；
- 封路和边界：位置、形状、五件事；
- 规划数据里的事件、资源、守点、安全屋，换算到压缩后的坐标；
- 每个元素的来源和状态。
